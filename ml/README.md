# `ml/` — Kasauti's Laya pipeline: train → calibrate → quantize → publish

Everything here exists to produce **one artifact**: a small, calibrated, quantized ONNX model that a
visitor's browser downloads from a public Hugging Face *model* repo and runs locally. No server
classifies anything, and no audio byte leaves the device on the web surface.

```
ml/banks.json                    question banks — the single source of truth for wording
ml/kasauti_ml/                   the pipeline (12 modules, no notebook-only code)
ml/scripts/                      generators: TS banks mirror, parity fixture, Kaggle notebook
notebooks/kasauti_laya_finetune_kaggle.ipynb   generated driver for the GPU run
public/dev-model/                a tiny export used by local dev + the browser E2E test
```

---

## 1. Five-minute local proof (CPU only)

You do not need a GPU to validate the chain. The `smoke` profile builds a ~0.5 M-parameter model
with a tiny tokenizer and pushes it through *every* stage: data → RLCD training → calibration →
gates → vocab pruning → fp32 export → INT8 + 4-bit export → ORT agreement → parity vectors →
manifest → staging with sha256 verification.

```bash
python -m ml.scripts.gen_banks_ts              # regenerate src/lib/banks.ts from banks.json
python -m ml.kasauti_ml.pipeline --profile smoke --out ml/out/dev --public-dir public/dev-model
```

Takes ~20 s and ends with:

```
[kasauti-ml] exported: fp32=2.0 MB  int8=0.6 MB  q4=1.5 MB
[kasauti-ml] quantization agreement: int8=1.0 (Δlogit 0.0029)  q4=1.0
[kasauti-ml] parity vectors: 10 tokenizer / 6 logits
[kasauti-ml] staged 3 artifacts in ml/out/dev/staging (all sha256 verified)
[kasauti-ml] dev model copied to public/dev-model
```

**Read the smoke run correctly.** The accuracy gates *will* fail there, and the pipeline says so and
carries on: a half-million-parameter randomly-initialised model cannot learn six decision banks in
half a minute. What the smoke run proves is the *plumbing* — export, hashes, quantization
agreement, parity vectors, manifest schema, and that the browser can load and run the result.
Accuracy is the GPU run's job (§3).

## 2. What the pipeline actually does

| stage | module | what it guarantees |
|---|---|---|
| banks → TS mirror | `scripts/gen_banks_ts.py` | the trainer and the browser can never ask different wording (`--check` fails CI on drift) |
| data | `datagen.py` | split **by template hash**, never by row: `template_overlap` must be 0 or the run aborts |
| training | `train.py` | RLCD — REINFORCE with a group-mean baseline, zero-mean Gaussian logit noise, strictly proper scoring, DDP across GPUs |
| calibration | `calibrate.py` | one temperature per `(type, option-count)` bucket + an abstention map that holds accepted-answer error under a target |
| gating | `evals.py` | accuracy, per-language floor, ECE (overall + per bucket), `noul`/`choice`, pay-to-withdraw P/R, impersonation recall, negative FPR, abstention coverage |
| export | `export.py` | lossless vocab pruning (row gather + merge closure + byte fallback, self-checked), dynamic-axes fp32 graph, INT8 (WASM), 4-bit `MatMulNBits` (WebGPU), ORT agreement |
| parity | `parity.py` | tokenizer id vectors + full-sequence logit vectors, so the browser can prove it matches |
| publish | `publish.py` | content-hashed filenames, manifest written last, every file re-hashed before upload |

Gates are **blocking** outside the smoke profile: a failed gate exits `2` and publishes nothing; INT8
agreement below 0.95 exits `3`. That is deliberate — shipping a subtly-broken quantized graph is the
one failure nobody catches in review.

### Layout of a published export

```
manifest.json                       schema 2: calibration, thresholds, hashes, evals, bank sha
kasauti-laya-int8.<sha8>.onnx       WASM path   (dynamic INT8)
kasauti-laya-q4.<sha8>.onnx         WebGPU path (4-bit MatMulNBits, block 32/64)
kasauti-laya-fp32.<sha8>.onnx       reference graph (parity + debugging)
tokenizer.json                      vocabulary-pruned tokenizer (ids remapped to match)
parity.json                         id vectors + logit vectors
```

The browser verifies `sha256` of every file against the manifest, and the manifest's `banks.sha256`
against its compiled-in `BANKS_SHA256`. A mismatch is surfaced in the UI instead of silently
degrading answers.

## 3. The GPU run (Kaggle, 2×T4)

Open **`notebooks/kasauti_laya_finetune_kaggle.ipynb`** (generated by `python -m ml.scripts.gen_notebook`)
and run the cells in order. Step by step:

1. **Settings** → Accelerator `GPU T4 ×2`, Internet `on`. Optionally add a Kaggle Secret `HF_TOKEN`
   with a Hugging Face **write** token (only step 9 needs it).
2. **Cells 0–1** — install deps, clone/attach the project.
3. **Cell 2** — configuration: `VARIANTS`, `EPOCHS`, `MICRO_BATCH`, `GRAD_ACCUM`, `MAX_LEN`,
   `PUBLISH_REPO`, `TASKS`.
4. **Cell 3** — provenance check. Prints the bank inventory and fails if `src/lib/banks.ts` is stale.
5. **Cell 4** — dataset build. Asserts zero template overlap and shows a real row.
6. **Cell 5** — the CPU smoke run (§1) *inside the notebook*, so a broken environment is found
   before you spend GPU minutes.
7. **Cell 6** — the fine-tune itself:

   ```bash
   torchrun --standalone --nproc_per_node=2 -m ml.kasauti_ml.pipeline \
     --profile kaggle --out /kaggle/working/out \
     --model-id convaiinnovations/laya --subfolder multilingual \
     --variants 40 --epochs 3 --micro-batch 8 --grad-accum 4 --group-size 4 \
     --lr-encoder 2.5e-5 --lr-head 1e-4 --max-len 1024 --head-max-len 256 \
     --abstain-target-error 0.15 --log-every 25
   ```

   Both T4s train **one** model (`DistributedDataParallel`, gradients averaged, rows sharded), and
   only rank 0 evaluates, calibrates, exports and publishes.
8. **Cells 7–8** — read the gate/calibration reports, then verify the artifacts independently:
   re-hash every file, re-run INT8 and 4-bit on the parity vectors against the fp32 reference, and
   confirm the graph still exposes `input_ids / attention_mask / marker_pos / marker_mask / qtype`.
9. **Cells 9–10** — copy `out/staging` to the notebook's output, optionally push it to a HF **model**
   repo, then follow the integration checklist printed at the end (env var, browser verification,
   troubleshooting table).

### Flags you will actually touch

| flag | default (kaggle) | notes |
|---|---|---|
| `--variants` | 40 | surface variants per template; more data beats more epochs here |
| `--epochs` | 3 | 5–6 when accuracy is short; watch eval ECE rise past that |
| `--micro-batch` / `--grad-accum` | 8 / 4 | effective batch 32; halve the first, double the second on OOM |
| `--max-len` / `--head-max-len` | 1024 / 256 | multilingual checkpoint values; 512/192 for short SMS-style states |
| `--tasks` | all six banks | narrower model = smaller, faster, sharper, less coverage |
| `--block-size` | 32 | raise to 64 when 4-bit agreement is below 0.95 |
| `--no-quantize-embedding` | off | keeps the embedding matrix fp16 (bigger, marginally safer) |
| `--abstain-target-error` | 0.15 | accepted-answer error the abstention map must hold |
| `--gates` | built-in | JSON file overriding gate thresholds for an experiment |
| `--publish-repo` | — | HF model repo id; `--hf-token` or `HF_TOKEN` needed |

`--profile smoke` defaults: 6 epochs, micro-batch 4, `max_len 192`, `head_max_len 64`. Explicit CLI
flags always win over profile defaults.

## 4. Integrating an export into the running app

Short version below; the operator's runbook (Kaggle setup, flags worth changing, gate table, verification, rollback) is [`../docs/kaggle-training-and-integration.md`](../docs/kaggle-training-and-integration.md).

1. Publish the whole `staging/` directory (never a subset — the graph and its tokenizer must come
   from the same run: pruning remaps ids).
2. Set the env var **before** building, because Next.js inlines it at build time:

   ```
   NEXT_PUBLIC_LAYA_MODEL_BASE=https://huggingface.co/<user>/kasauti-laya-multilingual-onnx/resolve/main
   ```

3. Redeploy, then open **`/dashboard` → On-Device Engine** and check:
   `modelVersion` = `kasauti-laya-multilingual@<sha8>`, backend `webgpu` (or `wasm-st`/`wasm-mt`),
   your fitted temperatures listed, **no** bank-drift warning, and **Inspect** showing the expected
   marker count.
4. Run a known scam through the Checker: a confident answer acts, an unsettled one shows
   *abstained* and the app reports Tier-0 only.
5. For local development and the Playwright E2E, `NEXT_PUBLIC_LAYA_MODEL_BASE=/dev-model` uses the
   bundled tiny export. It is a *plumbing* model: it loads and runs, its answers mean nothing, and
   the UI labels it as report-only.

## 4b. `reportOnly` — the honesty switch

`pipeline.py` writes `reportOnly: true` into the manifest when the run was `--profile smoke` **or**
when the eval gates failed. Smoke gates are advisory, so a dev export is staged anyway — but only for
inspection. The browser's `parseManifest()` reads that flag as *not calibrated*, the Worker forces
every abstention threshold to 1, and the UI shows a *report-only* chip: the model can be inspected and
can never move a verdict. A real, gate-passing `--profile kaggle` export does not carry the flag.

## 5. House rules (learned from the model card the hard way)

* `act_probability` is **never** a gate — the published card and issue #185 show it carries no
  usable signal. Gate on calibrated `confidence` (entropy over the option distribution).
* Never more than **20 options** in a `choice`: accuracy collapses above that. If a decision needs
  more, split it into a triage plus follow-ups.
* Keep questions **flat** (`choice` / `score` / `noul`). The model does not read nested structures.
* `noul` can follow its own `false:` / `true:` labels rather than the state (issue #156). Keep the
  two labels short and factual; the training data is built that way.
* Temperature must stay inside `[0.5, 5.0]` (`clamp_temperature`), or a bucket with few samples
  produces a meaningless scale.
* `per_channel=False` for the INT8 dynamic quantizer: per-channel collapses this model on the
  dynamic MatMulInteger path (upstream issue #790).
* An uncalibrated manifest is report-only. The Worker forces `abstain = 1` when a manifest is not
  schema 2, so a legacy or half-published export cannot trigger an action.

## 6. Regenerating the generated files

```bash
python -m ml.scripts.gen_banks_ts          # src/lib/banks.ts      (+ --check for CI)
python -m ml.scripts.gen_notebook          # notebooks/*.ipynb     (+ --check for CI)
python -m ml.scripts.make_tokenizer_fixture --repo convaiinnovations/laya-multilingual
                                           # tests/fixtures/laya-tokenizer.* (tokenizer parity gate)
```

`tests/tokenizer-parity.test.ts` replays Rust-`tokenizers` ids through the browser port — 44 texts,
every id compared, no tolerance. Regenerate the fixture whenever the port changes.
